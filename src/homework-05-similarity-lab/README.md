# 作業 5：向量相似度實驗

本題使用 **OpenAI Embeddings API** 把句子轉成向量，再以**餘弦相似度（cosine similarity）**計算句子之間的語意接近程度，並用 3 組測試文字驗證結果是否符合預期。

## 實作內容

- **Embeddings 程式**：`../shared/lib/embeddings.js` 使用共用的 OpenAI client，一次把多句送進 `text-embedding-3-small` 取得向量（1536 維）
- **相似度程式**：`similarity.js` 實作 `pairIndices`（產生兩兩組合）、`cosineSimilarity`（餘弦相似度）、`pairwiseSimilarity`（對一組向量算出全部兩兩分數，主程式實際呼叫的函式）與 `average`（平均分數）
- **測試資料**：`data/test-groups.js` 定義 3 組 × 3 句，每組附上 `expectation` 說明預期結果
- **主程式**：`index.js` 送出全部 9 句、依組切分向量，逐組印出兩兩相似度與平均值

相關檔案：

## 執行方式

1. 安裝依賴

```bash
npm install
```

2. 建立環境變數

```bash
cp .env.example .env
```

3. 在 `.env` 填入 `OPENAI_API_KEY`（本題只需要這一個變數）

4. 執行作業 5

```bash
npm run hw5
```

本題為一次性批次程式，執行完會直接輸出三組結果後結束，不需互動。

## 設計重點

- **一次送出全部 9 句**：`embedAll` 只呼叫一次 API，再由 `splitByGroup` 依各組句數切回三組，減少往返次數
- **分母仍完整計算**：`text-embedding-3` 系列回傳的已是單位向量（分母為 1），但 `cosineSimilarity` 仍計算 `‖a‖·‖b‖`，避免日後換成未正規化的模型時結果失真
- **維度檢查**：兩向量長度不一致時直接 throw，避免靜默算出錯誤分數
- **第 3 組刻意設計成「立場相反、主題相同」**：用來驗證 cosine 衡量的是語意方向（談論的主題）而非情感立場

## 測試結果

以下數值來自實際執行 `npm run hw5`，完整輸出見 [`demo-similarity-run.txt`](./demo-similarity-run.txt)。

模型：`text-embedding-3-small`，向量維度 1536。

### 第 1 組：意思相近的句子

(1) 我喜歡貓　(2) 貓咪很可愛　(3) 我養了一隻貓

| 句子組合 | 相似度 |
| --- | --- |
| (1) × (2) | 0.699 |
| (1) × (3) | 0.675 |
| (2) × (3) | 0.554 |
| **平均** | **0.643** |

### 第 2 組：意思不同的句子

(1) 今天天氣很好　(2) 我要去買菜　(3) 電腦壞了

| 句子組合 | 相似度 |
| --- | --- |
| (1) × (2) | 0.287 |
| (1) × (3) | 0.236 |
| (2) × (3) | 0.241 |
| **平均** | **0.255** |

### 第 3 組（自己設計）：立場相反但主題相同

(1) 這部電影非常好看，我大力推薦　(2) 這部電影非常難看，我完全不推薦　(3) 這部電影在講一位太空人想辦法回到地球的故事

| 句子組合 | 相似度 |
| --- | --- |
| (1) × (2) | 0.763 |
| (1) × (3) | 0.475 |
| (2) × (3) | 0.463 |
| **平均** | **0.567** |

## 結果分析

**第 1 組與第 2 組的差異符合預期。** 第 1 組三句都圍繞「貓」這個主題，兩兩相似度落在 0.554～0.699（平均 0.643）；第 2 組分屬天氣、採買、電腦故障三個不相干領域，兩兩相似度只有 0.236～0.287（平均 0.255），兩組平均相差約 0.39，明顯拉開差距，證實 Embeddings 確實把語意接近的句子放在向量空間中較近的位置。

**第 3 組的觀察：** 評價完全相反的兩句（0.763）反而比第 1 組任何一對都高，甚至高過同組中「正評 × 劇情描述」（0.475）。這說明餘弦相似度衡量的是**談論的主題與語境**，而不是**情感立場或事實正確性**——「非常好看，大力推薦」和「非常難看，完全不推薦」用詞高度重疊、談的都是同一部電影，因此向量方向極為接近。實務上做 RAG 檢索時要留意這點：相似度高只代表「講的是同一件事」，不代表「立場一致」，需要判斷正反意見時得再交給模型分析，不能只看分數。

## 驗收對照

- **能成功呼叫 Embeddings API 取得向量**：有，9 句一次取得 9 個 1536 維向量（見 `demo-similarity-run.txt` 第 3 行）
- **能計算並輸出兩兩句子的相似度**：有，每組 3 句輸出 3 組兩兩配對，共 9 個相似度數值
- **README 附兩兩相似度數值，並說明第 1 組與第 2 組的差異是否符合預期**：有，見上方「測試結果」與「結果分析」
